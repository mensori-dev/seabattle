# Онлайн: игра с другом по коду комнаты

Онлайн — отдельный режим рядом с игрой против бота. Офлайн-игра не меняется:
`file://`, PWA и APK работают без сервера.

```
js/online.js        клиент: WebSocket, комнаты, события (window.Online)
server/main.ts      сервер: комнаты, проверка флота, подсчёт выстрелов
```

## Как это устроено

1. Игрок A нажимает «Создать комнату» → сервер выдаёт 4-значный код.
   В лобби A заранее выбирает поле (8×8, 10×10, 12×12), флот
   (классический или адмиральский) и тактику.
2. Игрок B вводит код → оба попадают на расстановку. Конфиг комнаты
   приходит в `room` и `start`, гость его не выбирает.
3. Каждый отправляет свой флот. Сервер проверяет состав, границы, пересечения
   и касания (даже углами). Если в комнате включена тактика, клиент перед
   отправкой флота шлёт `loadout` — две способности из трёх.
4. Когда оба флота и лоудауты приняты, сервер случайно выбирает первого
   и присылает `begin` с конфигом, лоудаутом и `first`.
5. Выстрелы и способности считает **сервер**: клиент не знает чужой флот
   и не может подсмотреть его через DevTools. Клиент получает только
   `miss` / `hit` / `sunk` и клетки потопленного корабля.
6. Промах передаёт ход, попадание оставляет его. Авиаудар и дым тоже
   передают ход. Победа — когда потоплены все корабли. Комната после боя
   удаляется.
7. Онлайн-матчи не меняют ELO и не попадают в историю: рейтинг начисляется
   только в боях с ботом. Личные победы в онлайне считаются на устройстве,
   причём в счёт идут только классические комнаты (10×10, классический
   флот, без тактики).
8. Победы для таблицы «Лучшие в онлайне» сервер считает в памяти инстанса
   (`GET /api/leaderboard`). В базу данные не пишутся: топ обнуляется после
   перезапуска сервера. В топ попадают только классические комнаты.
   Клиент только рисует список.
9. Если вход по коду попал на другой инстанс Deno Deploy (комнаты живут
   в памяти), клиент сам переподключается и повторяет вход 2 раза.
   Финальная ошибка показывается, только когда все попытки исчерпаны.

Сообщения (JSON, поле `t`):

| От клиента | Что значит |
| --- | --- |
| `create` | создать комнату: `{ name, rating, config }` |
| `join` | войти по коду: `{ code, name, rating }` |
| `fleet` | расстановка: `[{ size, cells: [[x, y], …] }, …]` и `loadout` |
| `loadout` | две способности: `ids: ['airstrike', 'smoke']` |
| `ability` | способность: `{ kind: 'airstrike' \| 'aa' \| 'smoke', x, y }` |
| `shot` | выстрел `{ x, y }` |
| `surrender` / `leave` | сдаться / выйти |

| От сервера | Что значит |
| --- | --- |
| `room` | код комнаты, твой индекс и `config` |
| `wait` / `start` | ждём второго / второй зашёл (`foe`, `config`) |
| `fleetOk` / `foeReady` | флот принят / соперник готов |
| `begin` | бой начался: `first`, `config`, `loadout`, `foeLoadout` |
| `shot` | результат выстрела (`mine: true` — твой) |
| `turn` | чей ход |
| `ability` | результат способности: `kind`, клетки, `owner` / `foe` |
| `pass` | ход пропущен: стрелять некуда (всё под дымом) |
| `end` / `foeLeft` | конец боя / соперник вышел |
| `error` | текст ошибки для игрока |

`config` — `{ size: 8 | 10 | 12, fleet: 'classic' | 'admiral', tactics: boolean }`.
Сервер сам проверяет, что флот соответствует размеру поля и пресету, а
способности — лоудауту и остатку зарядов.

**Порядок выката:** сначала сервер (он понимает `config` и способности),
потом клиент. Старый клиент с новым сервером играет классику: сервер
подставляет конфиг по умолчанию. Новый клиент со старым сервером получает
`room` без `config`, показывает предупреждение «Сервер не обновлён» и
играет классическую комнату.

## Локальный запуск

Терминал 1 — сервер:

```
npm run server
```

(или вручную: `deno run --allow-net --allow-env server/main.ts`)

Терминал 2 — сайт:

```
npm run dev
```

На `localhost` клиент сам ходит на `ws://127.0.0.1:8000`; на сайте и в `file://`
используется прод-сервер из `PROD_URL`. Поэтому для локальной проверки онлайна
не нужно ничего менять в коде.

Проверка протокола без браузера — `npm run test:online` (сервер должен быть
запущен; скрипт `scripts/online-smoke.mjs`, можно указать свой URL аргументом).

Открой http://localhost:5173 в двух вкладках (или на двух устройствах в одной
сети — тогда замени `127.0.0.1` в `js/online.js` на IP компьютера).
Первая вкладка: «Играть с другом» → «Создать комнату». Вторая: ввести код.
Ссылка `http://localhost:5173/index.html?room=1234` заходит в комнату сразу.

Проверка сервера: http://127.0.0.1:8000/health → `{"ok":true,"rooms":0,"top":0}`.
Рейтинг: http://127.0.0.1:8000/api/leaderboard → `{"top":[{"name":"…","wins":1}]}`.

Топ побед живёт в памяти инстанса: после перезапуска он пустой. Это сделано
специально — сервер не хранит персональные данные (см. `privacy.html`, раздел 3).

## Деплой на Deno Deploy (бесплатно)

Нужен аккаунт GitHub или Google — карта не требуется. Бесплатного лимита
(100 000 запросов в сутки) хватает с большим запасом: одна партия — это
несколько десятков сообщений.

Используется Deno Deploy EA и CLI `deno deploy` (входит в Deno 2.9+).

### Один раз: организация и токен

1. Войди на https://console.deno.com через GitHub.
2. Создай организацию (например, `mensori-dev`).
3. **Account settings → Personal access tokens → Create a new token**,
   срок — 24 часа или неделя.

### Создать приложение и задеплоить

```powershell
$env:DENO_DEPLOY_TOKEN='<токен>'
deno deploy create server --org mensori-dev --app mensori-seabattle `
  --source local --runtime-mode dynamic --entrypoint main.ts --region eu `
  --build-timeout 5 --build-memory-limit 1024 --json --non-interactive
```

Получится `https://mensori-seabattle.mensori-dev.deno.net`. Проверка:
`https://mensori-seabattle.mensori-dev.deno.net/health` → `{"ok":true,"rooms":0,"top":0}`.
Отдельная база не нужна: сервер ничего не сохраняет между перезапусками.

### Обновить сервер после правок

```powershell
deno deploy server --org mensori-dev --app mensori-seabattle --prod --json --non-interactive
```

Entrypoint запоминается в настройках приложения, повторно указывать не нужно.

Для интерактивной работы без токена: `deno deploy create` (мастер) и
`deno deploy --prod` — CLI сам откроет браузер и сохранит сессию.

### Подключить адрес в игре

В `js/online.js` заполни константу:

```js
var PROD_URL = 'wss://mensori-seabattle.mensori-dev.deno.net/ws';
```

Важно: `wss://` (не `https://`) и обязательный `/ws` на конце. После правки
подними версию кэша в `sw.js` (`VERSION`), иначе у установленных PWA останется
старый клиент.

После деплоя токен можно отозвать: **Account settings → Personal access
tokens → Delete**. Токен даёт доступ ко всему аккаунту Deno Deploy.

## Свой VPS в России (рекомендуется)

Deno Deploy удобен, но это США: для РКН это трансграничная передача.
Свой сервер в РФ снимает вопрос и ускоряет комнаты.

Полная инструкция — `deploy/README.md`, установка одной командой:

```bash
sudo bash deploy/setup.sh <домен>
```

Скрипт поднимает Deno, systemd-юнит `seabattle`, nginx с `/ws` и
`/api/leaderboard`, TLS от Let's Encrypt. После установки меняется только
`PROD_URL` в `js/online.js`.

## Что важно помнить

- Сервер не хранит персональные данные: ники, флоты и выстрелы живут в памяти
  комнаты и исчезают после боя или через 2 часа. Топ побед тоже считается
  в памяти и обнуляется после перезапуска.
- Сервер хранит комнаты в памяти. Перезапуск/засыпание инстанса закрывает
  активные комнаты — для игры с друзьями это нормально.
- Комната живёт 2 часа, потом удаляется фоновой уборкой.
- Ники чистятся от управляющих символов и `<`/`>`, длина — до 16 символов.
- Один игрок — одно соединение: при обрыве соперник получает `foeLeft`.
- Heartbeat: клиент шлёт `ping` каждые 20 секунд после входа в комнату, сервер
  отвечает `pong`. Если `pong` не пришёл 45 секунд, клиент закрывает сокет и
  показывает кнопку «Подключиться заново». В скрытой вкладке сторожок спит, а
  после возврата сразу отправляет `ping`. Автоматического восстановления боя
  нет: сервер не хранит снапшот, поэтому прерванный матч не продолжается.
- Читить через клиент нельзя: флот и выстрелы проверяет сервер.
