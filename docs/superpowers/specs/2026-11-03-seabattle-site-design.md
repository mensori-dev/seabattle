# Сайт-витрина «Морского боя» — дизайн

Дата: 2026-11-03
Статус: черновик на согласование

## Зачем

Друзьям и знакомым нужно одно место, куда кидается ссылка: красивая страница,
из которой понятно, что за игра, и с которой можно поставить её на телефон —
Android (APK) или iPhone (unsigned IPA). Игра в браузере остаётся отдельной
страницей в корне сайта; витрина её не заменяет.

Успех: друг открывает ссылку с телефона, за 10 секунд понимает, что это,
и скачивает нужный файл без вопросов «а почему не ставится».

## Цели

- Одна статичная страница на русском, mobile-first, без сборщиков и фреймворков.
- Красиво: море, крупная типографика, скриншоты в рамках телефонов, лёгкая анимация.
- Две кнопки скачивания (APK и IPA), сайт сам определяет платформу и подсвечивает нужную.
- Понятная инструкция установки: Android — APK, iPhone — unsigned IPA через Sideloadly,
  плюс вариант «играть в браузере».
- Ссылка на актуальные файлы, версия и changelog обновляются при каждом релизе
  без ручной правки страницы.
- Каждый релиз автоматически обновляет сайт, GitHub Releases и OneDrive.

## Не цели

- Английская версия — отдельный этап после локализации игры.
- Аналитика, аккаунты, формы, backend.
- Замена игры на главной: `index.html` в корне остаётся игрой.
- Свой домен и отдельный репозиторий (см. подходы).

## Анти-цели

- Страница, где кнопки ведут на устаревшие файлы или на 404.
- Тяжёлая страница: больше ~2 МБ картинок на первом экране.
- Обещание «скачай и играй» для iPhone без оговорки про неподписанный IPA.

## Ограничения

- GitHub Pages отдаёт корень `main`; сайт живёт в `/site/`.
- Только классические IIFE в браузерных скриптах, без ES-модулей.
- Тач-цели ≥32px, уважать `prefers-reduced-motion`.
- Кнопки скачивания ведут на GitHub Releases (`/releases/latest/download/<asset>`),
  а не на файлы в git — репозиторий не должен пухнуть.
- Имена ассетов в релизе стабильные: `seabattle.apk`, `seabattle-unsigned.ipa`.
- Пуш и деплой — только после подтверждения пользователя (правило проекта).

## Рассмотренные подходы

**A. Лендинг в этом же репозитории, папка `site/`** — выбран.
Тот же GitHub Pages, ноль новой инфраструктуры, ссылка
`https://mensori-dev.github.io/seabattle/site/`. Минус — длинный адрес и общий
репозиторий с игрой; для витрины друзьям это неважно.

**B. Отдельный репозиторий + домен** — выглядит солиднее, но нужен домен, DNS
и второй деплой. Избыточно для «кинуть ссылку друзьям».

**C. Витрина на главной, игра в `/play/`** — ломает текущие ссылки, установку PWA
и офлайн-кэш. Отклонён.

## Структура страницы

1. **Hero**: название «Морской бой — Морская арена», слоган, две кнопки
   (основная — под платформу посетителя, вторая — «Играть в браузере» → `../index.html`),
   подпись «v1.3.0 · Android 5+ · iPhone (unsigned)».
2. **Скриншоты**: 5 кадров в рамках телефонов, горизонтальная прокрутка на мобильном.
3. **Что внутри**: 4 карточки — бот с ELO, онлайн-комнаты по коду, достижения,
   офлайн/PWA.
4. **Установка**: три карточки-таба:
   - Android: скачать APK → разрешить установку из неизвестных источников;
   - iPhone: скачать unsigned IPA → установить через Sideloadly/AltStore с компьютера;
   - Браузер: играть сразу, можно добавить на главный экран.
5. **Версия и changelog**: последние 3 пункта из release notes, ссылка на all releases.
6. **Подвал**: privacy.html, GitHub, RuStore (когда пройдёт модерация), e-mail/контакт.

## Визуальное направление

- Палитра: глубокий морской синий фон (#071a2b), светлый текст, коралловый акцент
  (#ff7a59) для кнопок, бирюзовый (#3ddad7) для деталей.
- Крупная типографика (system-ui, плотные заголовки), много воздуха.
- Фон hero: CSS-градиент + SVG-волны с медленной анимацией; отключается при
  `prefers-reduced-motion`.
- Скриншоты в рамках телефонов с лёгким наклоном/тенью; без 3D-перегруза.
- Никаких внешних шрифтов и CDN — страница работает и без сети (кэш браузера).

## Файлы

```
site/
  index.html      — разметка и тексты
  site.css        — стили, анимации, адаптив
  site.js         — определение платформы, табы установки, версия/changelog
  version.json    — генерируется при релизе: version, date, notes[]
  img/            — оптимизированные скриншоты (webp) и иконки
scripts/
  make-site-images.py   — из docs/screenshots/*.png делает site/img/*.webp
  release.mjs           — релизный шаг: сайт + GitHub Releases + OneDrive
```

Скриншоты не ссылаются на `docs/` напрямую: они пережимаются в `site/img/`
(ширина 720, webp, ~150–250 КБ), чтобы страница весила меньше 2 МБ.

## Скачивание

Имена ассетов остаются версионными, как в release notes:
`seabattle-<версия>-release.apk` и `seabattle-<версия>-unsigned.ipa`.
Ссылки на сайте строятся из `version.json`, то есть ведут ровно на файлы текущего
релиза:

- `https://github.com/mensori-dev/seabattle/releases/download/v<версия>/seabattle-<версия>-release.apk`
- `https://github.com/mensori-dev/seabattle/releases/download/v<версия>/seabattle-<версия>-unsigned.ipa`

Дублировать ассеты под «стабильными» именами не нужно: инструкция в release notes
и кнопки на сайте указывают на одни и те же файлы.

`site.js` показывает платформу: на Android основная кнопка — APK, на iOS — IPA,
на десктопе обе равнозначны. Если `version.json` не загрузился, кнопки ведут на
страницу релизов, а не на битую ссылку.

## Service worker игры

`sw.js` перехватывает любую навигацию по origin и кладёт её под `./index.html`.
Если открыть `/site/`, офлайн-кэш игры перезапишется HTML витрины, и PWA без сети
покажет лендинг вместо игры. Поэтому в `sw.js` добавляется ранний выход для
запросов, чей путь начинается с `/site/` (или `./site/`), и поднимается версия:
`VERSION = 'sb-v17'` + `SW_VERSION` в `js/app.js`.

Это правка игры, поэтому по правилам проекта APK и IPA пересобираются, версия
остаётся `1.3.0` / `versionCode 4` (в RuStore уходит тот же код), а в OneDrive и
GitHub Releases кладутся новые файлы.

## Автообновление при релизе

Новый `scripts/release.mjs` (запуск `npm run release`) делает по шагам:

1. Проверяет, что `dist/seabattle-<версия>-release.apk`, AAB и IPA собраны,
   `dist/RELEASE_NOTES.md` существует; версия берётся из `package.json`.
2. Генерирует `site/version.json` (версия, дата, 3 пункта из release notes).
3. `gh release create v<версия> dist/... --notes-file dist/RELEASE_NOTES.md`,
   при наличии релиза — `gh release upload --clobber`.
4. Обновляет OneDrive: `seabattle-<версия>.apk`, `seabattle-<версия>-unsigned.ipa`,
   `seabattle-<версия>-RELEASE_NOTES.md`, папки `seabattle-<версия>/` и
   `seabattle-rustore-<версия>/`; удаляет из OneDrive все `seabattle-*`
   предыдущих версий (оставляет только текущую).
5. Печатает чек-лист: что осталось сделать руками (commit, push).

Правило OneDrive после этого: там всегда только последняя версия. Старые
удаляются скриптом, вручную ничего чистить не нужно.

Правило проекта про подтверждение деплоя остаётся: `release.mjs` спрашивает
`--yes` для публикации релиза и правки OneDrive, без флага только показывает план.

## Доступность и качество

- Контраст текста ≥ 4.5:1, видимый focus, alt у скриншотов.
- Все интерактивные элементы доступны с клавиатуры; табы установки — на `<button>`
  с `aria-selected`.
- Проверка: браузерный смоук на 390×844 и 1440×900, клик по обеим кнопкам
  (HEAD-запрос к файлам), проверка `version.json` после релиза.

## Решено мной (можно поправить)

- Скачивание через GitHub Releases, ссылки строятся из `version.json` — имена
  файлов остаются версионными, как в release notes, поэтому инструкция и кнопки
  всегда совпадают.
- Скриншоты пережимаются в webp скриптом на Python/Pillow (уже есть в проекте).
- Тексты пишу сам в духе «сделал для друзей», без маркетингового пафоса.
- В подвале — только GitHub (issues) и privacy.html; личную почту не публикую.
  Если нужен Telegram — скажи, добавлю.
- RuStore-ссылка появится в подвале после модерации; до этого её нет.
- `sw.js` правится (исключение `/site/`) с подъёмом кэша до `sb-v17`; APK/IPA
  пересобираются, версия остаётся `1.3.0` / `versionCode 4`.

## Открытый вопрос

Один: **публикуем ли v1.3.0 на GitHub Releases сейчас** (тогда кнопки на сайте
работают сразу) или сначала сайт, а релиз — отдельным шагом после твоего «да».
Публикация тега и ассетов, как и правка OneDrive, — действие наружу.
