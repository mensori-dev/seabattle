# «Морской бой» 1.5.0 — кастомные лобби и тактический бой

Дизайн-документ. Дата: 2026-11-04. Статус: на согласовании.
Предыдущий блок: `2026-11-04-seabattle-1.4.0-block1-design.md` (выпущен как 1.4.0).

## Зачем

1.4.0 добавила косметику и музыку, но правила боя не менялись с первой версии.
1.5.0 даёт две вещи, за которыми возвращаются: **свои правила боя с другом**
(поле, флот, тактика) и **выбор способностей перед боем** — момент принятия
решения, которого сейчас нет.

Онлайн-матчи не влияют на ELO, поэтому кастомные лобби не ломают рейтинг.
Кастомный бой с ботом рейтинг не начисляет — иначе 5×5 с одним кораблём
превращается в ферму очков.

## Цели

- Хост создаёт комнату и выбирает: поле 8×8 / 10×10 / 12×12, пресет флота,
  включена ли тактика. Гость видит эти настройки до готовности.
- Тактический бой: экран подготовки с тремя карточками способностей,
  игрок выбирает **две из трёх**, каждая — один заряд на бой.
- Тактика работает и против бота, и в онлайне. Истина — на сервере.
- Классика не меняется: 10×10, классический флот, без тактики, ELO как сейчас.

## Не цели (1.5.0)

- Свободный конструктор флота (вручную набрать любые корабли) — 1.6.0.
- Скины, вода, шторм, прожекторы, реванш, эмодзи, тепловая карта, реплеи,
  сезонные кубки — 1.6.0.
- Рейтинг и достижения за кастомные бои.
- Автоматическое восстановление боя после разрыва соединения.
- Щит/броня кораблей — не делаем: пользователь прямо назвал это дизбалансом.
- Сборщик, фреймворк, ES-модули, внешние ассеты, стриминг музыки.

## Анти-цели

- Сломать запуск через `file://`.
- Сломать сборку Яндекс Игр (онлайн из неё вырезан — тактика должна работать
  с ботом и там).
- Дать клиенту решать исход выстрела, потопления или способности.
- Изменить ключ профиля `seabattle.profile.v2`.
- Сломать классический рейтинг и ежедневный бонус.

## Ограничения

- Браузерные скрипты — классические IIFE, без `import`.
- `js/engine.js` не знает про DOM; `js/app.js` не содержит правил игры.
- Онлайн остаётся сервер-авторитетным: сервер проверяет конфиг комнаты,
  флот и каждую способность.
- UI на русском, mobile-first, тач-цели новых элементов ≥ 44 px,
  `prefers-reduced-motion` уважается.
- Версия кэша PWA поднимается в `sw.js` и `js/app.js` одновременно.
- `npm test` зелёный после каждого шага; онлайн — `npm run test:online`.

## Подходы

| Вариант | Что даёт | Чем платим |
|---|---|---|
| **A. Лобби + тактика сразу в онлайне** (выбран) | Всё, что просил пользователь: свои правила и способности с другом | Сервер учится конфигу и трём способностям; риск рассинхрона выше |
| B. Кастом и тактика только против бота | Вдвое меньше работы | Главный сценарий — игра с другом — не получает ничего |
| C. Только кастомные лобби без тактики | Проще | Пользователь просил и то, и это |

Выбран A. Пользователь явно сказал: «1 варик, только в онлайн тоже надо».

## Как это устроено

### 0. Модель конфига боя

Одна структура на бота и на онлайн:

```
BattleConfig = {
  size: 8 | 10 | 12,          // по умолчанию 10
  fleet: 'classic' | 'admiral', // по умолчанию 'classic'
  tactics: boolean             // по умолчанию false
}
```

Пресеты флота по размеру поля (длины кораблей, порядок не важен):

| Поле | classic | admiral |
|---|---|---|
| 8×8 | `[3,2,2,2,1,1,1]` — 7 кораблей, 12 клеток | недоступен |
| 10×10 | `[4,3,3,2,2,2,1,1,1,1]` — 10 кораблей, 20 клеток | `[5,4,3,3,2,2,1,1,1,1,1]` — 11 кораблей, 24 клетки |
| 12×12 | `[5,4,4,3,3,2,2,1,1,1,1,1]` — 12 кораблей, 28 клеток | `[5,4,4,3,3,3,2,2,1,1,1,1,1]` — 13 кораблей, 31 клетка |

Экспорт из движка: `Engine.CONFIG`, `Engine.fleetsFor(size)` →
`{ classic: number[], admiral: number[] | null }`.

### 1. Движок: размер поля

Сейчас `SIZE = 10` используется в `inBounds`, `canPlace`, `placeShip`,
`rebuild`, `rotateShip`, `randomBoard`, `fire`, `allSunk`, `shipsLeft`,
`totalShips` и в боте. Доска уже хранит `board.size` — он просто не читается.

- Все функции берут размер из `board.size` (где доски нет — из параметра).
- `createBoard(size = Engine.SIZE)`.
- `randomBoard(fleet, size)`.
- Бот (`createBot`) читает `board.size` вместо константы; поведение и
  эвристики не меняются.
- `Engine.SIZE` остаётся экспортом и дефолтом — старые вызовы не ломаются.
- В `app.js` все `Engine.SIZE` заменяются на `state.size` (или `board.size`),
  `buildBoard` создаёт сетку `size × size`, CSS получает
  `style.setProperty('--n', size)`; в `style.css`
  `grid-template-columns:repeat(var(--n, 10), 1fr)`.

**Способности в движке.** Кроме `areaCells(size, side, x, y)`, движок
экспортирует:
- `Engine.abilitySide(size)` → `2` для 8×8 и `3` для 10×10/12×12;
- `Engine.ABILITIES` — три описания (id, имя, иконка, текст);
- `Engine.newAbilityState(loadout)` → заряды по каждой способности;
- `Engine.useAirstrike(board, x, y)` → `{ cells: [{x,y,result,ship}], sunk }`,
  меняет `board.shots` теми же правилами, что `fire`;
- `Engine.applySmoke(board, x, y, turns)` и `Engine.tickSmoke(board)`;
- `Engine.legalShots(board)` → список клеток, куда можно стрелять
  (учитывает дым) — им пользуются и сервер, и бот, и проверка дедлока.

Правила живут только здесь; `app.js` и `server/main.ts` вызывают движок
(сервер — через ту же логику, портированную в `main.ts` по образцу `fire`,
если импорт `engine.js` в Deno окажется неудобным).

### 2. Кастомные лобби (онлайн)

**Протокол.** Расширяем существующие сообщения, новых типов комнат нет.

- `create` → `{ t: 'create', config: BattleConfig }` (без конфига — классика).
- Сервер валидирует конфиг: `size` ∈ {8,10,12}, `fleet` есть для этого
  размера, `tactics` — boolean. Невалидный конфиг → `error`, комната не
  создаётся.
- `room` → `{ t: 'room', code, you, name, rating, config }`.
- `wait` — без изменений.
- `start` / `begin` → добавляется `config`.
- `fleet` → сервер проверяет флот **по конфигу комнаты**: количество и длины
  кораблей, границы `size`, касания. Ошибка — как сейчас, `error`.
- `shot` → границы по `config.size`.

**Клиент.** Экран создания комнаты получает блок настроек:
сегменты «Поле: 8×8 / 10×10 / 12×12», «Флот: Классика / Адмиральский»,
переключатель «Тактический бой». «Адмиральский» недоступен на 8×8.
Гость на экране ожидания видит строку «Поле 10×10 · Классика · Тактика».

**Ссылка-приглашение** `?room=1234` не меняется: конфиг приходит с сервера.

**Топ побед.** В `onlineWins` и серверный топ идут только классические
комнаты: 10×10, флот `classic`, без тактики. Кастомные комнаты в топ не
попадают — иначе 7 кораблей на 8×8 фармят таблицу быстрее классики.

**Порядок выката.** Сначала сервер (`deno deploy`), потом клиент на GitHub
Pages. Клиент проверяет, что в `room` пришёл `config`: если сервер старый и
конфига нет, экран комнаты показывает «Сервер не обновлён — кастомные
комнаты недоступны» и не даёт создать кастомную комнату. Обычная классика
продолжает работать со старым сервером.

**Бой с ботом.** В настройках (⚙️) появляются сегменты «Поле», «Флот» и
«Тактика» — те же, что в лобби; на экране расстановки видна строка-сводка
«Поле 8×8 · Классика · Без тактики». Настройки берутся из `botConfig` и
сохраняются при старте боя. Классика (10×10, любой флот, тактика выкл.)
остаётся настройкой по умолчанию, поэтому путь «открыл и играю» не меняется.
Если выбрано что-то кастомное, на экране подготовки и результата виден бейдж
«Без рейтинга».

### 3. Тактический бой

**Способности** — чистые данные в движке:

```
ABILITIES = {
  airstrike: { id: 'airstrike', name: 'Авиаудар', icon: '✈️', desc: '...' },
  aa:        { id: 'aa',        name: 'ПВО',      icon: '🛡️', desc: '...' },
  smoke:     { id: 'smoke',     name: 'Дым',      icon: '💨', desc: '...' }
}
```

**Подготовка.** После расстановки флота, если `config.tactics` — экран
«Выбери две способности»: три карточки, выбор ровно двух, кнопка «В бой»
активна при двух. Выбор запоминается в профиле (`loadout: string[]`),
по умолчанию — `['airstrike','smoke']`. В онлайне экран показывается обоим
после `fleetOk`; выбор уходит на сервер сообщением `{ t: 'loadout', ids }`.

`begin` в тактической комнате отправляется только когда пришли **оба**
`loadout`. Если один игрок не прислал выбор за 60 секунд, сервер сам берёт
его последний сохранённый лоудаут (или `['airstrike','smoke']`) и начинает
бой — комната не может зависнуть на подготовке.

**Правила.**

| Способность | Радиус | Эффект | Ход |
|---|---|---|---|
| Авиаудар | 3×3, на 8×8 — 2×2 | Каждая ещё не обстрелянная клетка получает обычный выстрел: промах/попадание/потопление и раскрытие корабля. Дым не мешает: авиаудар бьёт и по задымлённым клеткам | Тратит ход, доп. хода не даёт |
| ПВО | — | Пассивно, автоматически: первый авиаудар соперника бьёт только свою центральную клетку 1×1 | Не тратит, срабатывает само |
| Дым | 3×3, на 8×8 — 2×2 | Зона на своём поле: соперник не может стрелять в эти клетки 3 своих хода | Тратит ход |

Прицеливание: для 3×3 тапнутая клетка — **центр**, область не выходит за
границы (центр 1…n-2). Для 2×2 тапнутая клетка — **левый верхний угол**,
область прижимается к границам. Клиент и сервер считают область одной и
той же чистой функцией движка `areaCells(size, side, x, y)`.
Если все клетки области уже обстреляны — серая подсветка и отказ
(«Здесь уже всё обстреляно»), заряд не тратится.

**Сервер.** Новое сообщение `{ t: 'ability', kind, x, y }`:
- проверить, что сейчас ход игрока и способность есть в его лоудауте,
  заряд не потрачен, координаты в границах;
- авиаудар: пересчитать все клетки области, отправить обоим одно событие
  `{ t: 'ability', kind: 'airstrike', x, y, cells: [{x,y,result,ship}], foe: bool }`,
  затем обычный `turn`;
- дым: `{ t: 'ability', kind: 'smoke', x, y, owner: 0|1, turnsLeft: 3 }`;
  в `shot` сервер отклоняет выстрел в клетку под дымом с `error`;
- ПВО: сервер сам гасит авиаудар до центральной клетки и рассылает
  `{ t: 'ability', kind: 'aa', blocked: true }` обоим;
- заряды хранятся в комнате, не на клиенте.

**Краевые случаи ПВО.** Сработавшее ПВО расходуется; заряд авиаудара
атакующего тоже тратится, ход переходит — это честная цена неудачного
удара. Если центральная клетка уже обстреляна, удар не наносит урона, но
ход и заряды всё равно расходуются. ПВО не тратится, если авиаудар так и
не был применён.

**Счётчик дыма.** Дым тикает, когда заканчивается ход соперника (после
выстрела или способности). Если у соперника не осталось ни одной законной
клетки для выстрела (всё оставшееся под дымом), сервер сам пропускает его
ход событием `{ t: 'pass', reason: 'smoke' }`, счётчик тикает — ход не может
зависнуть. Дым нельзя ставить так, чтобы под ним не было ни одной
необстрелянной клетки.

**Бот.** Те же правила, что у игрока: в начале партии выбирает две
способности (эвристика: авиаудар + дым), применяет авиаудар по зоне с
известным попаданием, дым — вокруг своего повреждённого корабля, ПВО
срабатывает само.

**UI боя.** Панель способностей под полем противника: две кнопки с иконкой и
счётчиком заряда. Нажатие включает режим прицела (подсветка области),
повторное — отменяет. На телефоне — те же кнопки, тап по полю применяет.

### 4. Экран подготовки (карточки)

Отдельный экран между расстановкой и боем:
- заголовок «Выбери две способности»;
- три карточки в ряд (на узком экране — колонкой): иконка, название,
  одна строка описания, бейдж «1 заряд»;
- выбранные — бирюзовая рамка и галочка, невыбранная — приглушена;
- кнопка «В бой» активна ровно при двух выбранных;
- анимация выбора уважает `prefers-reduced-motion`;
- доступность: `role="button"`, `aria-pressed`, фокус с клавиатуры,
  тач-цель ≥ 44 px.

### 5. Рейтинг, кубок и бонусы

- Рейтинговый бой с ботом: `size === 10 && tactics === false`, флот —
  любой из двух пресетов. Адмиральский — фиксированный пресет без
  преимущества, поэтому он остаётся рейтинговым, а достижение «Адмирал»
  остаётся достижимым.
- «Кубок моря» переосмыслен в **«Испытание дня»** (`§9`): три боя подряд без
  поражения с фиксированным на сутки конфигом, одинаковым для всех. Награда —
  +60 к рейтингу один раз в день; сами бои идут по общим правилам гейта.
- Нерейтинговый бой: ELO, победы/поражения, серия, рекорд, ежедневный
  бонус и достижения не меняются. Пополняются только история (с пометкой
  «без рейтинга») и точность стрельбы.
- Онлайн, как и раньше, ELO не меняет; топ побед — только классические
  комнаты (см. §2).

### 6. Профиль

В `seabattle.profile.v2` добавляются поля (ключ не меняется):
`loadout: string[]`, `lobby: BattleConfig` (последние настройки комнаты),
`botConfig: BattleConfig` (поле/флот/тактика для боя с ботом). Старое
поле `fleet` продолжает читаться как флот для бота, пока `botConfig` нет.
Чтение — с дефолтами, неизвестные значения отбрасываются.

### 7. Яндекс Игры и `file://`

- Онлайн в сборке Яндекса вырезан — тактика и кастомное поле работают
  против бота, конфиг берётся из настроек.
- `file://` не использует ничего нового, кроме localStorage — работает.

### 8. Кэш

Правки `index.html`, `style.css`, `js/*` → поднять `VERSION` в `sw.js` и
`SW_VERSION` в `js/app.js` одним шагом.

### 9. Испытание дня (бывший «Кубок моря»)

Кубок оставался тремя боями подряд без поражения, но игрался всегда на
классике — то есть не давал повода трогать новые настройки. Теперь это
**испытание дня**: конфиг на сутки фиксирован и одинаков для всех, кто заходит
в игру в этот день.

- Пресеты дня (по кругу, детерминированно от даты):
  1. «Классика» — 10×10, classic, без тактики.
  2. «Блиц» — 8×8, classic, с тактикой.
  3. «Малый флот» — 8×8, classic, без тактики.
  4. «Адмирал» — 10×10, admiral, без тактики.
  5. «Большое поле» — 12×12, classic, без тактики.
  6. «Армада» — 12×12, admiral, с тактикой.
- Карточка в меню показывает название дня и конфиг, например
  «🎯 Испытание дня · Армада · 12×12».
- Нажатие ставит `botConfig` в конфиг дня и начинает цепочку из трёх боёв.
  Поражение сбрасывает цепочку, как и раньше.
- **Награда:** +60 к рейтингу за пройденные три боя, один раз в день.
  Это единственное исключение из правила «кастом — без рейтинга»: конфиг
  одинаков для всех и даётся раз в сутки, поэтому фармить его быстрее
  классики нельзя.
- Сами бои подчиняются общему гейту: если конфиг дня не 10×10 или с
  тактикой, ELO за отдельные бои не начисляется, но завершение цепочки
  всё равно даёт +60.
- Достижение `cup` переименовывается в «Испытание дня»; id не меняется,
  чтобы не ломать профиль.

Экспорт движка: `Engine.dailyChallenge(dayKey)` →
`{ id, name, config, desc }`. Функция детерминирована: одна и та же дата даёт
один и тот же пресет, разные даты — разные (по кругу).

## Решения по итогам проверки

Проверка спеки «свежим инженером» нашла места, где планировщику пришлось бы
угадывать. Решения приняты и уже внесены в разделы выше; здесь они собраны
одним списком, чтобы при реализации не перечитывать весь документ.

1. **Кубок моря** — только рейтинговые бои (`§5`). Кастомный конфиг не даёт
   +60 и не двигает раунды. Начатый кубок при смене настроек на кастомные
   просто не получает награду — отдельных диалогов не делаем.
2. **Нерейтинговый бой** замораживает ELO, победы/поражения, серию, рекорд,
   ежедневный бонус и достижения; пишет только историю с пометкой и точность
   (`§5`). Иначе «Без рейтинга» было бы неправдой.
3. **Достижение «Адмирал»** остаётся достижимым: адмиральский флот —
   фиксированный пресет без преимущества, поэтому бой 10×10 с ним остаётся
   рейтинговым (`§5`).
4. **Два конфига в профиле**: `lobby` для комнат и `botConfig` для бота;
   старое поле `fleet` читается как фолбэк (`§6`). Настройки комнаты не
   перетирают настройки бота.
5. **Авиаудар бьёт и по дыму** — дым запрещает только обычные выстрелы
   (`§3`). Иначе дым становится неуязвимым щитом, а его пользователь прямо
   назвал дизбалансом.
6. **Дедлок дыма закрыт**: дым тикает в конце хода соперника, а если у него
   не осталось законных клеток, сервер сам шлёт `pass` (`§3`). Дым нельзя
   поставить так, чтобы под ним не было ни одной необстрелянной клетки.
7. **Краевые случаи ПВО** описаны явно: срабатывание расходует и заряд
   атакующего, и его ход; повторное ПВО не срабатывает; ПВО не тратится,
   пока авиаудар не применён (`§3`).
8. **`begin` ждёт оба `loadout`** с таймаутом 60 секунд и авто-выбором —
   комната не может зависнуть на подготовке (`§3`).
9. **Прицеливание**: 3×3 — тапнутая клетка центр, 2×2 — левый верхний угол;
   одна чистая функция `areaCells` на клиенте и сервере (`§3`, `§1`).
10. **Топ побед и выкат**: в топ идут только классические комнаты; сервер
    обновляется раньше клиента, старый сервер без `config` показывает
    понятную ошибку и не ломает классику (`§2`).
11. **Поле**: 8×8, 10×10, 12×12 — других размеров нет, меньше краевых
    случаев. Флот пресетами, без ручного конструктора.
12. **Способности**: выбор двух из трёх, по одному заряду; авиаудар и дым
    масштабируются 3×3 / 2×2; дым живёт 3 хода соперника.

## Что оставлено реализатору

- Точные эвристики бота для способностей.
- Анимации карточек, дыма и авиаудара.
- Формулировки описаний способностей.
- Порядок карточек и иконки (эмодзи допустимы).
- Внутренняя структура хранения зарядов, если тесты покажут удобнее иначе.

## Критерии приёмки

1. Хост создаёт лобби 8×8 с классическим флотом, гость видит настройки и
   играет на 8×8; сервер отклоняет флот на 10×10.
2. Лобби 12×12 с адмиральским флотом и тактикой: оба проходят подготовку,
   видят три карточки способностей и выбирают по две; кнопка «В бой» не
   активна, пока выбрана одна.
3. Экран подготовки выглядит как выбор карт: три крупные карточки с иконкой,
   названием, описанием и бейджем «1 заряд», выбранные подсвечены, работает
   с клавиатуры и на телефоне (тач-цель ≥ 44 px).
4. Авиаудар 3×3 накрывает несколько клеток, потопление раскрывает корабль,
   ход переходит сопернику, второй авиаудар недоступен.
5. ПВО гасит первый авиаудар соперника до 1×1, расходует заряд и ход
   атакующего; повторный удар ПВО не гасит.
6. В клетку под дымом сервер не даёт стрелять 3 хода соперника, потом даёт;
   авиаудар по задымлённым клеткам проходит.
7. Если у игрока все оставшиеся клетки под дымом, сервер сам пропускает его
   ход — бой не зависает.
8. Игрок, не выбравший способности за 60 секунд, получает авто-лоудаут и бой
   начинается.
9. Классический бой с ботом 10×10 без тактики по-прежнему меняет ELO, серию,
   победы и ежедневный бонус; бой 10×10 с адмиральским флотом — тоже.
10. Кастомный бой с ботом (8×8/12×12 или тактика) не меняет ELO, победы,
    серию, рекорд, бонус и достижения, показывает «Без рейтинга» и пишет
    историю с пометкой.
11. «Кубок моря» начисляет +60 только в рейтинговом бою; кастомный конфиг
    награду не даёт.
12. Кастомная комната не попадает в топ побед онлайн; классическая —
    попадает.
13. Старый сервер без `config`: классика работает, кастомная комната
    показывает «Сервер не обновлён — кастомные комнаты недоступны».
14. `npm test` и `npm run test:online` зелёные; `file://` играется;
    сборка Яндекса собирается и играет с ботом на 8×8 и 12×12.

## Риски

| Риск | Что делаем |
|---|---|
| Размер поля зашит в ~60 местах — можно пропустить одно | Тест на 8×8/12×12 в движке + смоук на всех трёх размерах |
| Рассинхрон клиента и сервера в способностях | Сервер считает всё сам, клиент только просит и рисует ответ; `areaCells` — общая формула |
| Авиаудар слишком силён на маленьком поле | 2×2 на 8×8, один заряд, ход тратится |
| Дым раскрывает информацию (где нет кораблей) | Дым виден обоим, но не раскрывает клетки — только запрещает выстрелы |
| Дым блокирует все ходы и бой зависает | Сервер сам шлёт `pass`, дым нельзя ставить на полностью обстрелянную зону |
| Кастомные бои ломают экономику рейтинга | Без ELO/кубка/бонуса/достижений вне классики; кастомные комнаты вне топа |
| Старый сервер и новый клиент расходятся | Выкат сервер → клиент; клиент проверяет `config` в `room` и честно сообщает |
| Онлайн-тесты станут нестабильными | Расширяем существующий `scripts/online-smoke.mjs` сценариями конфига и способностей |
| Экран подготовки перегружен на маленьком экране | Карточки колонкой, тач-цели ≥ 44 px, проверка на 360 px |
